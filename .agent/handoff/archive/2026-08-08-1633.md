## 試したこと・結果

### 成功したアプローチ

- **★固まりの判定に `ps -o %cpu` を使う。** 画面が描かれていても当てにならない。
  ステータスバーの時計はシステムが描くのでアプリの生死と無関係。100%張り付き＝レイアウトの無限ループ
  ```bash
  PID=$(pgrep -f "Subsc.app/Subsc" | head -1); ps -p $PID -o %cpu=
  ```
- **★原因の切り分けは、疑う部分を消したビルドを作って比べる。** 推測でパッチを当てない。
  **導入前のコミットを別ワークツリーでビルドしてCPUを比較**するのが最短だった
  ```bash
  git worktree add <path> <導入前のref>   # 作業ツリーを汚さず比較できる
  ```
- **★タップ座標は実スクショから測る。** 表示画像は縮小されていて実寸と縦横比が違う。
  PILで目標色の帯を探して pt へ換算する（3xなので /3）。目視換算で30pt以上ずれ、
  「押しても反応しない＝固まっている」と誤診した
- **★イラストは画像生成を挟んでからベクター化する。** 座標を手で置く方法では
  SVGを4回作って4回とも破綻した（目が「00」に見える／ヒゲが顔から飛び出す／頭と胴がつながらない）。
  **Codexに1024pxのPNGを生成させ、それを輪郭抽出してベジェ化**したら一発で成立した。
  トレース用のコードは `scratchpad/trace.py` と `scratchpad/build_cat.py`（**セッションが変わると消える**）
- **Codexの報告は毎回こちらで検証した。** 「104pxで全パーツ判別できた」は嘘ではないが、
  **判別できることと良く見えることは別**だった。色・禁止要素・パーツの有無を自分で確認してから採否を決めた
- **AskUserQuestion で方向を固定してから委譲した。** それでも4往復かかったが、
  固定しなければもっとかかっていた

### 失敗したアプローチ・つまずき

- **★【最重要】CPUを測らずに「動作確認済み」と報告し、固まる版をコミット・pushした。**
  タップが数回通ったことをもって確認済みとした。実際は `ScrollView(.horizontal)` +
  `LazyHStack` + `containerRelativeFrame` + `.scrollTargetBehavior(.paging)` の組み合わせが
  レイアウト無限ループを起こしていた。**この組み合わせを使ってはいけない**
- **原因を `GeometryReader` だと決めつけ、`ViewThatFits` に直してコメントまで書いた。** 全くの誤診で、
  `ViewThatFits` 版でも100%のままだった。**推測を書き残すと次の人を誤らせる**
- **`TabView(.page)` は固まらないが、自分の枠を越えて中身を描く。**
  操作部を `VStack` で並べると文字を大きくしたとき本文が重なる。
  `.clipped()` も地を敷くのも `zIndex` も効かない。**`overlay` に載せる**と必ず上に描かれて解決した
- **`ReportPager` の重複 `makePage` を1回にまとめたらCPU100%になった。**
  ページの中身が `currentStep` に依存すると「位置が動く→中身が変わる→再レイアウト→位置が動く」の循環。
  **重複は意図的なものとして残し、理由をコードに書いた。** 直そうとしないこと
- **アイコンで黒地に黒い顔を置いて失敗した。** 29ptで顔が沈んで猫だと分からない。
  **金の面に黒を抜く**という現行の構造が正しかった
- **SVGに `width`/`height` 属性を書くと縮小されない。** `viewBox` だけにする
- **`qlmanage` でのラスタライズは透過を保持しない。** 背景が白で塗られ、色の面積測定が無意味になる
- **`pgrep -f codex` は ChatGPTアプリ本体と常駐 `codex app-server` も拾う。**
  実際に動いているかは `ps -o %cpu` で判断する
