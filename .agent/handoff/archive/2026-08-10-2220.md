## 試したこと・結果

### 成功したアプローチ

- **★判断を2箇所に持たせない。** 「その月に計上するか」を自前で書かず、
  `ReportCalculator.includes` を切り出して公開し、カレンダーもそれを通す形にした。
  カレンダーが足すのは**「月のどの日か」だけ**。
  さらに**「月内の日合計の総和＝レポートの月合計」を不変条件としてテストで縛った**
- **★テストと実装を同時に書いたら、変異を入れて確かめる。** 丸めを外す／フィルタを外す、を
  実際にやって該当テストだけが落ちることを確認した。RED を踏めないときの代わりになる
- **★見た目を先に作ると、仕様の矛盾が実装前に出る。** モックを作った段階で
  「モックは停止中を合計に含める／SPECは含めない／レポートは月によって違う」という
  **3つ巴の食い違い**が見つかった。実装後に気づいていたら作り直しだった
- **pbxprojのUID書式は既存から機械的に導く。** `AA` + 6桁ゼロ埋め + 埋め草 + 番号（計24字）。
  既知の値（122 と 23）で検算してから生成し、`plutil -lint` と `xcodebuild -list` で検証した
- **xcodebuild の出力はファイルへ落としてから数える。** パイプで grep すると行を取りこぼす

### 失敗したアプローチ・つまずき

- **★【最重要】検証を足したら、その検証が誤報を出す条件を考えていなかった。**
  通知の欠落を数える仕組みが、**未許可の環境で全件を「欠けている」と数え**、
  「54件が予約できませんでした。上限は64件です」という自己矛盾した警告を出した。
  **上限64に対し54なら上限超過ではない。数字を読めば分かる。**
  → `authorizationStatus` を見て `authorized` / `provisional` 以外では数えない
- **★知らせの本文だけを持ち回していた。** `operationError: String?` を3種類の知らせで
  使い回し、見出しは `"データを同期できませんでした"` 固定。**通知の話が同期の失敗として
  表示されていた**。見出しと本文を組（`OperationAlert`）で持たせて直した
- **★日付を1日間違えたまま記録していた。** 8/9から日をまたいでいたのに、
  カレンダーの作業を全部 2026-08-09 と書いていた（実際は 8/10）。
  `.spec/` 4ファイルとコード内コメント2箇所を訂正済み。
  **`date` を実行して確かめる。** context の日付と実際の時刻がずれることがある
- **ハンドオフの `mtime` は当てにならない。** マージやチェックアウトで書き換わる。
  アーカイブ名は**内容の見出し日時**か、`git log` で実際の作成時刻を確かめて決める
- **`.spec/TODO.md` の「次の空き番は161」は正しかったが、確認の仕方を誤って一度220と読んだ。**
  正規表現が `AA0001` の直後3桁を拾い、番号が末尾にある書式と食い違っていた。
  **UIDは末尾の数字が番号。** 迷ったら python で全件パースする
