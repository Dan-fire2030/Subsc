## 試したこと・結果

### 成功したアプローチ

- **分割の粒度を「既存型の移動のみ」に絞った。** `body` 内の「次の更新」セクションを新しい View 型として抽出する案もあったが、新型を作ると「行の多重集合を比較して差分ゼロ」の機械的検証が効かなくなる。既存の `private` 型を移すだけでも 670行 → 最大339行に収まり目安を満たせた。**「もっと細かく割れる」より「機械的に安全と言える」を優先する**のが正解だった
- **正規化差分ゼロの検証は今回も効いた。** 手順は `.spec/KNOWLEDGE.md` に記録済み。ただし除外・正規化の対象はファイルごとに足す必要がある（今回は `import SwiftData` と `private enum` を追加）。macOS の `sed`/`grep` は `\s` を解釈しないので `[[:space:]]` を使うこと
- **pbxproj の登録を Python で機械的に行い、各アンカーに `assert` を置いた。** 4箇所（PBXBuildFile / PBXFileReference / PBXGroup / Sources）すべてで置換前にアンカー存在を検証したため、静かに登録漏れする事故を防げた。登録後は `grep -c` で各ファイルが4行に現れることと `plutil -lint` で確認
- **使用率ガードで「取れるか」を先に実測した。** `rate_limits` はステータスラインの stdin にしか来ず、フックの stdin には含まれない。既存の `statusline-command.sh` が既にその値を読んでいるのを見つけ、「ステータスラインがキャッシュ → フックが読む」という橋渡し設計に落とした。実装前に供給源を特定したので手戻りゼロ
- **ガードを発火すべきでないケースから先にテストした。** 6ケース中5ケースが「無音で exit 0」であるべきもの。誤発火のほうが実害が大きいので、そちらを厚くした

### 失敗したアプローチ・つまずき

- **シミュレーターパネルを開いたつもりで開いていなかった。** セッション冒頭の `attach` が「already attached」を返し、前セッションのアタッチ状態が残っていて誤判定されていた。**`detach` → `attach` し直すと「Simulator panel opened」が返り実際に開く。**
  さらに厄介なのは、**パネルが出ていなくてもスクリーンショットとタップ注入は動く**こと。「操作できているからパネルも出ている」と誤認した。MEMORY.md に記録済み
- **セグメンテッドPicker に注入タップが届かない。** 絞り込みピッカー（すべて/利用中/停止中/履歴）はどの座標でも選択が変わらなかった。**同じ画面・同じ換算比で `NavigationLink` の行タップと「戻る」ボタンは成功している**ので、座標変換の問題ではなく Picker 固有の制約。追いかけるのをやめて TODO に回した。KNOWLEDGE.md に記録済み
- **座標換算は「成功した要素」から逆算するのが早い。** 一覧行を画像座標から換算した (150,777) は外れたが、「次の更新」行の (150,543) は当たった。比率を再計算するより、**当たった点を基準に補正する**ほうが速い
- （前回からの継続）**シミュレーターMCPでフォームの金額欄に入力できない**。棒グラフと詳細シートの目視確認はこれが原因で未達のまま
