## 試したこと・結果

### 成功したアプローチ

- **「なぜ発火しないか」を推測で終わらせず、キャッシュの経過秒数で裏を取った。** ファイルの mtime だけでなく
  `date +%s` との差（71,691秒）を出したことで「前回セッションを丸ごと通しても更新されていない」が確定し、
  「ステータスラインがこの環境では呼ばれていない」まで一息で詰められた。**時刻の証拠は差分で示すのが早い**
- **壊れた設計を直さず、依存そのものを外した。** 使用率の供給源を探し直す選択肢もあったが、
  「常時有効なルール」にすれば使用率という不安定な入力が不要になる。**発火条件を持つ仕組みは、
  発火条件が壊れると無言で死ぬ**。ユーザーの「考えるのはClaude、実行はCodex」への転換がそのまま解決になった
- **配置先を実証してから書いた。** `~/.claude/CLAUDE.md` が無いのに rules/*.md が読み込まれている事実
  （システムプロンプトに9ファイル全部が入っていた）と、`settings.json` に参照リストが無いことの両方を確認し、
  「ディレクトリ単位の自動読み込み」と断定してからファイルを置いた
- **優先順位を「線引き」と「呼び出し方」に分離した。** 当初は「プロジェクトのAGENTS.mdを優先」と書いたが、
  それだと一本化の指示が既存プロジェクトで無効になる。**揃えたいもの（実行経路）と、プロジェクトごとに
  違ってよいもの（何を委譲するか）を分けて書く**ことで両立した
- **書き換え後に「禁止形の言及」と「実際の呼び出し」を区別して grep した。** 単純な `grep -c "codex exec"` では
  全ファイルがヒットして意味がない。`grep -v "叩かない"` で除外し、実行例が0件であることを示した
- **管制室とmake_projectの干渉調査は「書き込みAPIの不在」で示した。** `writeFileSync|writeFile|appendFile|
  mkdirSync|rmSync|unlink` を全文検索して0件 → 読み取り専用と断定。**「たぶん干渉しない」ではなく
  「書く手段を持っていない」と言える形にする**のが再現性のある結論になる

### 失敗したアプローチ・つまずき

- **zsh の `echo` が JSON を壊し、スクリプトのバグだと誤認しかけた。**
  `echo "$out" | jq` で「control characters must be escaped」が出たが、**zsh の `echo` は引数中の `\n` を
  実際の改行に展開する**ため、JSON文字列内のエスケープが壊れていただけ。スクリプトの出力は正しかった。
  **シェルスクリプトのJSON出力を検証するときは `printf '%s'` を使うか、一度ファイルへ落として読む。**
  MEMORY.md に記録済み
- **`cat -A` は macOS では使えない**（`illegal option -- A`）。不可視文字を見たいときは `cat -e` か
  ファイルへ落として `od` を使う
- **`grep -c` は0件のとき exit 1 を返す**ので `|| echo 0` を付けると `0\n0` になり、`[ ]` の数値比較が壊れる。
  件数を変数で扱うなら `grep -c ... || true` ではなく、素直に結果行を変数へ入れて空判定するほうが安全
- （継続）**シミュレーターMCPでフォームの金額欄に入力できない**。棒グラフと詳細シートの目視確認は未達のまま
- （継続）**セグメンテッドPicker に注入タップが届かない**。座標変換の問題ではなくPicker固有の制約
