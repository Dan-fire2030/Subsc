## 試したこと・結果

### 成功したアプローチ

- **返済額は電卓で先に検算してからテストへ置いた。** 目視では正しさが分からず、間違っていても
  「それっぽい数字」が出る領域。Python で `P*r/(1-(1+r)^-n)` を再現し、
  総利息・完済回数まで出してからテストを書いた
- **丸め誤差を事前に潰した。** 「当初元本から4回進めた残高」と「今の残高から」の予定表が
  一致するかを、実装前に Python で確認（**誤差ゼロだった**）。実装後に悩まずに済んだ
- **予定表は常に計算結果、実績が唯一の入力。** 滞納・繰上返済を記録すると予定表を丸ごと組み直すが、
  **記録した状態は計算より優先**され上書きされない。これで「滞納したら後ろへずれる」が自動で効く
- **通知の応答は「読み解き」だけを純粋関数に切り出した。** 受け取り自体はアプリ本体の文脈が要り
  テストできないが、識別子とボタンの解釈はテストできる

### 失敗したアプローチ・つまずき

- **`.highPriorityGesture` は ScrollView に効かない**（午前の作業。詳細は `.spec/KNOWLEDGE.md`）
- **ローンの通知が、更新日通知の再スケジュールで全部消える状態だった。**
  名前空間は接頭辞で判定していて、更新日通知は「`subsc-` で始まり `subsc-remind-` で始まらないもの」を
  自分のものと見なす。`subsc-loan-` を足すと誤認して掃除対象にする。
  → **除外を追加し、「どの識別子も、主張する名前空間はちょうど1つ」をテストで縛った。**
  **名前空間を増やすたびに同じ穴が開く**ので、コードにも警告を書いた
- **識別子のパースで UUID が切れかけた。** `subsc-loan-<clientID>-<periodKey>` の clientID は
  UUID で、ハイフンを4つ含む。**前から分割すると途中で切れる。** 末尾から年月を切り出す実装にした
- **Swift 6 の並行性チェックで `UNUserNotificationCenterDelegate` が通らなかった。**
  クラスを `@MainActor` にすると「non-Sendable な引数をアクターへ送れない」で落ちる。
  → デリゲートを `nonisolated` にし、**通知から文字列だけを取り出してから MainActor へ渡す**
- **`spread` は1回では埋まらない**（午前の作業）。半径が広がらないぶん外接矩形が伸びず約5%残る
- **Xcode の同期グループを使っていないプロジェクトだった。**
  新規ファイルは `project.pbxproj` の**4箇所**（`PBXBuildFile` / `PBXFileReference` / グループ / `Sources`）へ
  手動登録が必要。ID は `BB0000<NN>0000000000000<NN>` 形式で、**次に空いているのは 96**
- **`errorDescription` で暗黙 return と明示 return を混ぜてコンパイルエラー。**
  Swift は switch 式の全ケースで揃える必要がある
- **`xcodebuild` の相対パス指定で3回失敗。** Bashツールの作業ディレクトリが呼び出しごとに
  リポジトリルートへ戻ることがある。**`-project` は必ず絶対パスで渡す**
- **ディスクが100%で `xcodebuild` が落ちた**（午前）。DerivedData を削除して21GB回復
