以下の手順でハンドオフを作成してください：

1. `.agent/handoff/HANDOFF.md` が存在する場合：
   - そのファイルの更新日時（ローカル時刻）を取得
   - `.agent/handoff/archive/YYYY-MM-DD-HHMM.md` にリネーム

2. 新しい `.agent/handoff/HANDOFF.md` を以下のテンプレートに従って作成し、完了後「HANDOFF.mdを作成しました」と報告してください。各項目には、現在までのチャット履歴や作業内容からAI自身が自己の行動を要約し、具体的な内容を記入してから保存してください。単なる空のテンプレートのまま保存してはいけません。

書くときの原則：
- **次のセッションの自分が、この文書だけで作業を再開できること**を基準にする。会話を読み返さないと分からない書き方をしない
- **失敗と、その原因・回避策を必ず残す。** 同じ失敗を次のセッションで繰り返させないことが、この文書の最大の価値
- 完了したものは成果物とコミットハッシュ、未完了のものは「どこまで進んだか」「次に何をすれば終わるか」を書く
- **人間にしかできない作業**（実機確認・外部サービスへの入力・認証情報の設定など）は、代行できない旨を明記して分ける
- 作業領域が複数ある場合（本体リポジトリ / リポジトリ外の設定 など）は `###` で領域ごとに分ける

---
# HANDOFF - {日時}

## 使用ツール
Claude Code / Codex CLI / Gemini CLI など、該当するツール名とモデル名を記載。
主要ツールを使わなかった場合は「未使用」と書き添える

## 現在のタスクと進捗
- [x] 完了したタスク：成果物、コミットハッシュ、マージ・push先
- [ ] 未完了のタスク：どこまで進んだか、次に何をすれば終わるか

## 試したこと・結果

### 成功したアプローチ
- 何をして、なぜうまくいったか。次も使える形で書く

### 失敗したアプローチ・つまずき
- 何を試して、どう失敗したか。判明した原因と、採用した回避策

## 次のセッションで最初にやること
1. 最初のアクション
2. 次のアクション

## 注意点・ブロッカー
- 未コミット・未マージのまま残しているもの
- 人間しか解決できない事項（認証・権限・実機確認・外部サービスの入力）
- 壊してはいけない前提や、触ってはいけないもの
- 検証用に残しているデータ・一時的な状態
