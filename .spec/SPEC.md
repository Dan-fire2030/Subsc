# A. ローンの一時停止

## A-1. 目的

失業・産休・返済猶予などで**一時的に返済を止めた期間**を、アプリ側でも表せるようにする。
今は止める手段が無いため、止めているあいだ滞納として積み上がるか、
毎月「返済した」と嘘の記録を付けるしかない。

## A-2. 停止の意味（最重要）

**期日を後ろへずらすだけ**とする。

| 項目 | 停止中の扱い |
|---|---|
| 残高 | **減らない。増えもしない** |
| 利息 | **発生させない**。停止期間ぶんの利息は乗せない |
| 返済回数 | 減らない。停止した月は回数に数えない |
| 完済予定日 | **停止した月数ぶん後ろへずれる** |
| 総利息 | 変わらない |

**滞納（`missedPeriods`）とは別物**である点に注意する。滞納はその月の利息が残高へ繰り入れられ、
総利息が増える。一時停止は増えない。**同じ仕組みで実装してはならない。**

> 理由：haruto さんの選択。金融商品としての「返済据置」は利息が乗るのが実態だが、
> 計算とテストが重くなるうえ、利用者が知りたいのは「いつ終わるか」であって、
> 据置利息の厳密な額ではない。**違う数字を出すより、単純で説明できる規則を採る**
> （遅延損害金を計算しないと決めたのと同じ判断・前サイクル SPEC 4-6）。

### A-2-1. 繰り延べの持ち方

**`Loan` に繰り延べ月数のフィールドを増やさない。**

予定表は `LoanPayment` として保存済みで、まだ来ていない回は `status == .scheduled` で残っている
（`LoanSummary.make`）。したがって**再開時に、残っている `scheduled` の回の `dueOn` を
停止した月数ぶん後ろへ書き換えれば**、繰り延べはそのまま永続化される。

- 停止した月数 ＝ `pausedOn` から再開日までの**満月数**（`Calendar` の `dateComponents([.month])`）
- 0ヶ月（同じ月のうちに再開した）なら**何も書き換えない**
- 書き換えた `dueOn` は `paymentDay` へ丸め直す（前サイクルで踏んだ月末ずれの再発を防ぐ）

## A-3. データモデルの変更

`Loan` へ2フィールド追加する。**CloudKit Production への再反映が発生し、不可逆。**

| プロパティ | 型 | 既定値 | 備考 |
|---|---|---|---|
| `isPaused` | `Bool` | `false` | 停止中かどうか |
| `pausedOn` | `Date?` | `nil` | いつ停止したか。再開時の繰り延べ月数の算出に使う |

- CloudKitミラーリングの制約どおり、**既定値付きか Optional** にする（`AGENTS.md` の該当節）
- `LoanPayment` は変更しない（`dueOn` を書き換えるだけで、フィールドは増えない）
- **`pausedOn` は Optional なので、値を保存するまで CloudKit にフィールドが作られない。**
  代表データで実際に停止操作をしてから Console の差分を確認する（前サイクルで学んだ手順）

### 不変条件

- `isPaused == true` のとき `pausedOn` は必ず非 nil。停止操作で必ず両方を書く
- 再開時に `isPaused = false` と `pausedOn = nil` を**同時に**書く
- **`isClosed == true`（完済）のローンは停止できない。** 停止操作の入口自体を出さない

## A-4. レポートでの扱い

**サブスクの停止と同じ規則に揃える。**

- 停止中のローンは、**現在および未来の期間**の集計に含めない
- **過ぎ去った期間の集計には停止フラグを効かせない。** 停止前の月の実績はレポートに残す
- 今日を含む期間は「過去」に入れない（`ReportCalculator.swift:209` の既存規則をそのまま使う）

> **前サイクルで実際に踏んだ不具合（Codexレビュー Medium 6 / 2026-08-02 修正）**。
> サブスク側は「いつ停止したかを記録していない」ため期間の新旧だけで判断しているが、
> **ローンは `pausedOn` を持つので、より正確に「停止日より前の期間は残す」と判断できる。**
> ただし規則を2つ持つと食い違うため、**表示上はサブスクと同じ挙動に見えること**を優先し、
> 判定は既存の期間ベースに合わせる。`pausedOn` は繰り延べ計算に使う。

## A-5. 通知での扱い

- 停止中のローンには**返済日通知を予約しない**
- 停止操作をした時点で、そのローンの予約済み通知を**取り消す**
- 再開時に**予約し直す**（`dueOn` を書き換えた後に行う。順序を逆にすると古い期日で予約される）
- **名前空間 `subsc-loan-` は変えない。** 通知の取り消しは自分の名前空間の中だけで行う
  （`NotificationNamespace.contains` の既存の作りを壊さない）

## A-6. 予定表の自動進行

`LoanPaymentStore.settlePastDue` は、返済日を過ぎた `scheduled` の回を自動で返済済みへ移す。

- **停止中はこれを走らせない。** 走らせると、止めているあいだに勝手に返済済みが積み上がり、
  一時停止が無意味になる
- 再開時は、`dueOn` を書き換えた**後で**通常どおり走らせる

## A-7. 操作

### A-7-1. ローン詳細画面（`LoanDetailView`）

- 「一時停止する」／「返済を再開する」ボタンを置く
- 停止中は、いつから停止しているかと**完済予定が後ろへずれること**を画面上で伝える
- 完済済み（`isClosed`）のときはボタンを出さない

### A-7-2. 一覧のスワイプ（`DashboardView.loanRow`）

**leading（左から右）に「停止」／「再開」を置く。** trailing には何も足さない。

> **削除スワイプとは衝突しない。** `DashboardView.swift:314` のコメントのとおり、
> ローン行にはそもそも削除スワイプを付けていない（返済記録がまとめて消えるため、
> 確認を挟める詳細画面からだけ消せる）。
> さらに**サブスク行は leading＝停止/再開、trailing＝削除**という前例があるので、
> ローンも leading に置けば操作方向がサブスクと揃い、削除とは反対方向に分かれる。

- `allowsFullSwipe: false`（既存に合わせる。誤操作でいきなり実行されない）
- ラベルとアイコンはサブスクと同一：停止＝`pause.fill`・オレンジ、再開＝`play.fill`・緑

### A-7-3. 編集フォーム

**トグルは置かない。** 保存を押すまで反映されず、スワイプ／ボタンと挙動が食い違うため。

## A-8. 一覧での見せ方（`LoanRow`）

- 行全体の不透明度を下げる（サブスクの停止中と同じ値に揃える）
- 「停止中」バッジを出す
- 並び順は変えない。**「次の期日」で費目と混ぜる既存の並びに残す**
  （停止中は次の期日を持たないため、既存の nil の扱いに従う）

## A-9. テスト（`SubscTests`）

TDDで進める。**日付は `Calendar(identifier: .gregorian)` と固定日付**を使い、実行日に依存させない。

- 停止→3ヶ月後に再開で、残りの `scheduled` の `dueOn` が**ちょうど3ヶ月**後ろへずれること
- そのとき**総利息と残高が変わらない**こと（滞納との違いを固定する）
- 同じ月のうちに再開したら**何もずれない**こと
- 繰り延べ後の `dueOn` が `paymentDay` へ丸め直されること（31日指定で2月を跨ぐ場合）
- 停止中は `settlePastDue` が回を進めないこと
- 停止中のローンが**現在の期間**のレポートから外れ、**過去の期間**には残ること
- 停止中のローンに通知が予約されないこと／再開で予約し直されること
- 完済済みのローンは停止できないこと

# B. レポートグラフのガラス表現

## B-1. 目的

レポートカードのグラフを、**色の意味を保ったまま**ガラスらしい質感にし、
バブルは**ふわふわ浮いている**ように見せる。

## B-2. 適用範囲

**4スタイル全部**に同じガラス表現を当てる。

| ファイル | スタイル |
|---|---|
| `BubbleChart.swift` | バブル（円） |
| `GlassBarChart.swift` | 縦バー |
| `StackedBarChart.swift` | 積み上げ1本帯 |
| `ConcentricRingChart.swift` | 同心リング |

- バブルの**吹き出し（`BubbleCallout`）も含める**
- 表現は**1箇所に共通化**する（`ReportGlassStyle.swift` へ足す）。
  4ファイルへ個別に書くと、後から質感を揃え直せなくなる

## B-3. ガラスの見た目

**色を残したまま半透明ガラス。** シャボン玉のような虹色には寄せない。

> 理由：費目・種別の色分けが情報そのもの（前サイクル SPEC の色の決定）。
> 透過を強くしすぎると4色の区別が付かなくなり、グラフとして機能しなくなる。

- **iOS 26**：`glassEffect(.regular.tint(<種別色/費目色>.opacity(...)), in: .circle)` を使う
- **iOS 17〜25**：半透明の塗り ＋ 内側の光沢 ＋ 縁のリムライトでフォールバックする
  （`ReportCardSurfaceModifier` と同じ二段構えの流儀）
- **見込み（`isEstimated`）の半透明表現を潰さない。** ガラス化で全体が薄くなるため、
  見込みと確定の差が消えないことを目視で確認する
- ラベル（白文字）の可読性を落とさない。**背後が明るいときに白が飛ばないこと**を確認する

## B-4. 浮遊のアニメーション

現在は上下に最大3ptだけ（`BubbleNodeView` の `driftOffset`）。これを拡張する。

- **上下と左右を別々の周期で往復**させ、8の字に近い軌跡にする
- 円ごとに**周期と位相をずらす**（既存の `driftIndex` の考え方を踏襲）
- 振れ幅は**円同士が重なって見えない範囲**に抑える。半径に対する比で決める既存の方針を保つ
- **`reduceMotion` のときは一切動かさない**（既存の分岐を維持する）
- 脈動（拡大率の伸縮）は**入れない**（haruto さんの選択。ラベルが揺れるため）

## B-5. 壊してはいけないもの

- **`blocksPaging` の `onChange` に `initial:` を付けない**（隣のページが打ち消す）
- カード本体の慣性スライド、バブルのズーム／パン、ダブルタップのリセット
- 小さい円のタップ判定（`handleTap` の座標変換）。**装飾を足して当たり判定をずらさない**
- 縦バーの横スクロール（慣性）とページ送りの切り分け

## B-6. テスト

見た目の検証はユニットテストで担保できない。**動きと質感は目視で確認する**（A-10 の確認依頼に含める）。
ただし以下は自動で守る。

- 既存のチャート関連テストが通り続けること
- レイアウト計算（`BubbleLayout`）に手を入れた場合、円が重ならない不変条件のテストを足す

# C. 進め方

## C-1. ブランチ

**2本に分ける。**

| ブランチ | 内容 | ベース |
|---|---|---|
| `feat/loan-pause` | A. 一時停止 | `feat/loan-repayment` |
| `feat/glass-charts` | B. ガラス表現 | `feat/loan-repayment` |

> 理由：Aは**不可逆な CloudKit Production 反映**を伴う。Bは無関係な見た目の変更なので、
> Aの反映待ちや切り戻しにBを巻き込まない。

## C-2. CloudKit の反映（不可逆）

`AGENTS.md` の要求どおりに進める。**手順を省かない。**

1. モデルへフィールドを追加し、ビルドとテストを通す
2. Development 署名のアプリで**実際に停止操作をして**代表データを保存する
   （`pausedOn` は Optional なので、値が入るまでフィールドが作られない）
3. CloudKit Console で **Development と Production の差分を一覧にする**
4. 反映される Record Type とフィールドを提示し、**不可逆であることを明示して `AskUserQuestion` で承認を得る**
5. Deploy する（**1回目が `XHR request failure` で落ちても再試行する**）
6. 反映後、Production 側のフィールドを**1件ずつ読んでモデルと突き合わせる**
7. `AppStore/RELEASE_RUNBOOK.md` の「ローン機能で追加したスキーマ」を更新する

実機・目視でしか確かめられないもの。

- ガラス表現の見え方（iOS 26 の実機。開発機には iOS 26 のランタイムしかない）

- 停止中バッジの見え方と、詳細画面の文言
- 一覧スワイプの操作感（誤操作しないか）
