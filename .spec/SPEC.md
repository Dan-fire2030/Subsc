# SPEC - 要件定義

対象：Subsc iOSネイティブ版（`ios/Subsc`）。**借金・ローンの返済管理**。

> **状態：ヒアリング完了（2026-08-02）。実装着手前にユーザー承認が必要。**
> 決定はすべて `AskUserQuestion` で確認済み。理由は各節に残す。

---

## 1. 目的

サブスク・固定費に続き、**借金とローンの返済**を同じアプリで扱えるようにする。
毎月いくら返しているか、あと何回で終わるか、繰上返済でどれだけ早まるかを1つの画面で把握できる状態を作る。

---

## 2. スコープの決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| リリース | **1.0.0 に含める** | 審査提出を後ろ倒しして本機能を入れる |
| データの持ち方 | **別モデル `Loan` を新設** | 元本・利率・返済回数・残高はサブスクと構造が違う。既存の `Subscription` を汚さない |
| 返済方式 | **元利均等 / 無利息 / リボ（残高スライド定額）** | 元金均等は対象外 |
| 金利種別 | **固定 / 変動**。変動は現在の利率で試算し、変更時に手入力 | シナリオ比較は作らない。実装が軽く実態にも合う |
| 滞納時 | **完済予定日が1ヶ月後ろへずれる** | 残高は減らず、その間の利息は乗る。利用者に一番分かりやすい |
| 遅延損害金 | **計算しない** | 契約ごとに率も起算日も違い、正確に出せない。**違う数字を出すより出さない** |
| レポート | **月間・年間に含め、種別で絞り込める** | 毎月の支出全体が1画面で見える |
| 実績記録 | **予定表から自動で進む＋返済日当日の通知で確認** | 下記5節 |
| 繰上返済 | **期間短縮型のみ** | 返済額軽減型は対象外 |
| ボーナス返済 | **対応する** | 住宅ローン・カーローンでは一般的で、無いと予定表が実態と合わない |
| 登録方法 | **「当初元本＋借入日」と「現在の残高＋残り回数」の両方** | 大半の利用者は途中から登録する。契約書が手元に無くても始められる |
| 課金 | **予定表までは無料、試算は Pro** | 下記8節 |
| 通貨 | **日本円のみ** | 外貨建てローンは対象外。既存のUSD対応はサブスクに限る |

## 3. データモデル

**CloudKitミラーリングの制約を必ず守る**（`AGENTS.md` の該当節を参照）。
すべての保存プロパティに既定値かOptionalを持たせ、一意制約を使わず、配列はCSV文字列で持つ。

### 3-1. `Loan`（新規Record Type）

| プロパティ | 型 | 既定値 | 備考 |
|---|---|---|---|
| `clientID` | String | `""` | 既存モデルと同じ流儀 |
| `name` | String | `""` | 借入先・名称（例：住宅ローン、奨学金） |
| `note` | String | `""` | 自由メモ |
| `repaymentMethodRaw` | String | `"equalPayment"` | 元利均等 / 無利息 / リボ |
| `interestTypeRaw` | String | `"fixed"` | 固定 / 変動 |
| `annualRatePercent` | Double | `0` | 現在の年利 |
| `rateHistoryCSV` | String | `""` | 変動金利の履歴。`2026-04-01:1.2,2026-10-01:1.5` |
| `originRaw` | String | `"fromOrigin"` | 当初元本から / 現在残高から |
| `originalPrincipal` | Double | `0` | 当初元本 |
| `borrowedOn` | Date? | `nil` | 借入日 |
| `totalInstallments` | Int | `0` | 総返済回数 |
| `startingBalance` | Double | `0` | 「現在残高から」のときの開始残高 |
| `startingInstallments` | Int | `0` | 同・残り回数 |
| `startedTrackingOn` | Date? | `nil` | 同・その残高の基準日 |
| `paymentDay` | Int | `27` | 毎月の返済日 |
| `bonusMonthsCSV` | String | `""` | ボーナス返済月。`6,12` |
| `bonusAmount` | Double | `0` | ボーナス月の上乗せ額 |
| `slidingTiersCSV` | String | `""` | リボの残高スライド。`300000:10000,500000:15000` |
| `isClosed` | Bool | `false` | 完済・解約 |
| `createdAt` / `updatedAt` | Date | 現在時刻 | |

**`rateHistoryCSV` と `slidingTiersCSV` は computed property で構造体に出し入れする。**
`leadDaysCSV` と同じ流儀。配列を直接保存するとCloudKitミラーリングが壊れる。

**利率履歴を別モデルにしない理由**：Record Type を増やすほどProduction反映の不可逆な決定が増える。
履歴は「日付と率」の対で十分表現でき、既存のCSV流儀に収まる。

### 3-2. `LoanPayment`（新規Record Type）

各回の返済。**予定表から自動生成し、実績で上書きする。**

| プロパティ | 型 | 既定値 | 備考 |
|---|---|---|---|
| `clientID` | String | `""` | |
| `year` / `month` | Int | `0` | `AmountEntry` と同じ流儀 |
| `installmentNumber` | Int | `0` | 何回目か |
| `dueOn` | Date? | `nil` | 返済日 |
| `scheduledAmount` | Double | `0` | 予定額（元金＋利息） |
| `actualAmount` | Double? | `nil` | 実績。nilなら予定どおり |
| `principalPortion` | Double | `0` | 元金分 |
| `interestPortion` | Double | `0` | 利息分 |
| `statusRaw` | String | `"scheduled"` | 予定 / 返済済 / 滞納 / 繰上返済 |
| `recordedAt` | Date? | `nil` | |
| `loan` | `Loan?` | `nil` | リレーション |

### 3-3. `CostType` への追加

既存の enum に **`.loan`（借入・ローン）** を追加する。
rawValue 保存で unknown フォールバックがあるため、追加は互換的に行える。
レポートの絞り込みとグラフの色分けが、既存4種別と同じ仕組みでそのまま効く。

## 4. 計算仕様

**ビューから切り離した純粋な計算として `LoanScheduleCalculator` に置く。**
`ReportCalculator` と同じく、`calendar: Calendar = .current` を既定値付き引数で注入する。

### 4-1. 元利均等

月利 `r = 年利 / 12 / 100`、回数 `n`、元本 `P`。

- `r > 0` のとき：毎月返済額 `= P * r / (1 - (1 + r)^(-n))`
- `r == 0` のとき：`= P / n`（ゼロ除算を避けるため分岐する）
- 各回：`利息 = 残高 * r`、`元金 = 返済額 - 利息`、`残高 -= 元金`
- **最終回は端数を元金へ寄せ、残高を必ず0にする**

### 4-2. 無利息

`毎月返済額 = P / n`。最終回で端数を調整する。

### 4-3. リボ（残高スライド定額）

`slidingTiers` から、その時点の残高が属する帯の定額を引く。
`利息 = 残高 * r`、`元金 = 定額 - 利息`。

**`元金 <= 0` になる帯設定は不正**（永久に減らない）。入力時に弾き、日本語で理由を伝える。

### 4-4. ボーナス返済

`bonusMonthsCSV` の月は `bonusAmount` を上乗せし、**全額を元金へ充当する**。
上乗せぶん完済が早まる。

### 4-5. 変動金利

`rateHistoryCSV` の各適用日以降、その率で計算する。
**未来の利率は現在の率が続く前提で試算する。** 予測はしない。

### 4-6. 滞納

その回を飛ばし、**以降の予定を丸ごと1ヶ月後ろへずらす**。
残高は減らず、次回の利息は据え置かれた残高から計算される。結果として総返済額が増える。
**遅延損害金は加算しない。**

### 4-7. 繰上返済（期間短縮型）

指定額を全額元金へ充当し、残りの回数を再計算する。
毎月の返済額は変えない。**「今◯円入れると何ヶ月早まり、利息がいくら減るか」を出す。**

---

## 5. 返済実績の記録

1. 契約内容から**返済予定表を自動生成する**
2. **返済日当日にローカル通知を出す。** 通知アクションで「返済した」「滞納」を選べる
   - 通知を長押しして**アプリを開かずに記録できる**
   - 通知の識別子は `subsc-loan-<clientID>-<year><month>` とする。
     **既存の `subsc-<clientID>-...` の書式は壊さない**（別の名前空間にする）
3. 何もしなければ**予定どおり返済されたものとして扱う**
4. **滞納を選ぶとその月の返済額は0になり**、以降の予定が1ヶ月ずれる
5. **金額はあとから編集できる。** 繰上返済もこの編集で扱う

## 6. 画面

| 画面 | 内容 | 課金 |
|---|---|---|
| 一覧への統合 | 費目一覧に「借入・ローン」種別として並ぶ | 無料 |
| ローン詳細 | 残高、次回返済日、完済予定日、進捗 | 無料 |
| 返済予定表 | 各回の日付・返済額・元金・利息・残高 | 無料 |
| 返済履歴 | 返済済・滞納の記録と編集 | 無料 |
| 繰上返済の試算 | 「今◯円入れると何ヶ月早まるか」 | **Pro** |
| 利率変更の影響試算 | 利率を変えたときの返済額と総額の変化 | **Pro** |
| 借入シミュレーター | 未登録で試せる。借入額・利率・期間から返済額を出す | **Pro** |

## 7. レポートへの反映

- 月間・年間レポートに**返済額（元金＋利息の合計）を含める**
- 既存4種別と同じく**種別で絞り込める**
- グラフ（帯・リング・バブル・縦バー）は `CostType` の追加だけで対応できる
- **見込み扱いにはしない。** 予定表から確定的に決まるため

---

## 8. 課金の線引き

さきほど決めた収益化方針（`.spec/KNOWLEDGE.md` 2026-08-02）に従う。

- **1.0.0 では全機能を無料で出す。** 課金の実装は含めない
- Pro化は**リリース3ヶ月後に継続率を見てから**判断する
- **Pro候補は「試算」に限る**（繰上返済・利率変更・借入シミュレーター）。
  登録・残高・返済予定表の閲覧は**恒久的に無料**とし、後から制限しない
- **したがって、試算系の画面は最初から分離して実装する。** あとから切り出すのは難しい

---

## 9. 対象外（明記）

- 元金均等返済
- 遅延損害金の計算
- 返済額軽減型の繰上返済
- 外貨建てのローン
- 金融機関との連携・明細の自動取り込み（**審査向けの前提を壊さない**）
- 利率のシナリオ比較（「+0.5%ならどうなるか」の並列表示）

---

## 10. 審査・プライバシーへの影響

- **外部送信は増えない。** 計算はすべて端末内で完結する
- 通知は引き続き**iOSのローカル通知のみ**
- **プライバシーポリシー本文の更新が必要**（保存する情報に借入情報が加わる）。
  現行本文は最終更新2026年7月27日で、固定費・変動費すら反映されていない
- App Store の掲載文・スクリーンショットを作り直す必要がある
- **「アプリ内課金なし」の前提は1.0.0では維持される**（課金は3ヶ月後の判断）

---

## 11. CloudKit の作業（不可逆・要注意）

**Record Type が2つ増える**（`CD_Loan` / `CD_LoanPayment`）。`CD_Subscription` に追加はない。

1. Development署名のアプリで、**全プロパティに値を入れた代表データを保存する**
2. CloudKit Console で `CD_Loan` / `CD_LoanPayment` のフィールドを1件ずつ突き合わせる
   - **Optionalなプロパティは値を保存するまでフィールドが作られない。**
     `borrowedOn` `startedTrackingOn` `actualAmount` `recordedAt` `dueOn` が該当。
     **前回 `CD_endDate` でこの事故を起こしている**
3. Production へ Deploy（**不可逆・haruto さんの操作**）

## 12. テスト方針

`LoanScheduleCalculator` を純粋計算として切り出し、**TDDで進める**。

- 元利均等の返済額が既知の値と一致すること（電卓で検算した値を固定で置く）
- 利率0%でゼロ除算しないこと
- 最終回で残高がちょうど0になること
- 滞納で完済予定日が1ヶ月ずれ、総利息が増えること
- ボーナス返済で完済が早まること
- 繰上返済で回数が減り、総利息が減ること
- リボで元金が増えない帯設定を弾くこと
- 「現在残高から」と「当初元本から」で、同じ状態を表す入力が同じ予定表を出すこと
- **日付は `Calendar(identifier: .gregorian)` と固定日付を使い、実行日に依存させない**
