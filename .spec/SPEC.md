# SPEC - 要件定義

対象：Subsc iOSネイティブ版（`ios/Subsc`）。レポートカードの可視化スタイル。

> **状態：確定（2026-08-01）。**

## 目的

レポートカードの費目別グラフを、**全体の構成比が伝わる表現**へ作り替える。
見た目の魅力と独創性を高めつつ、現状の「9件中2件しか見えない」情報量の少なさを解消する。

表現は1つに絞らず、**4種類を用意して利用者が設定画面で選べる**ようにする。

## 用語

- **スタイル**：グラフの表示方法。4種類（帯 / リング / バブル / 縦バー）
- **種別**：`CostType`（サブスク／通信費／光熱費／その他固定費）
- **見込み**：変動費で実績が無く、直近の実績から推定した額（`ReportEntry.isEstimated`）

## 要件

### R0. 集計単位は「期間」で決める（2026-08-01 変更）

**当初は「A・Bは種別集計、C・Dは費目ごと」とスタイルで決めていたが、期間で決める方式へ変更した。**

| 期間 | 絞り込み | 集計単位 | 色 |
|---|---|---|---|
| **年間換算** | なし（すべての種別） | **種別ごと**（最大4） | 種別の4色 |
| 年間換算 | 種別で絞り込み中 | **費目ごと** | 利用者が費目に決めた色 |
| **月間換算** | 問わない | **費目ごと** | 利用者が費目に決めた色 |

**年間かつ絞り込みなしのときだけ種別集計**になる。絞り込み中に種別で集計すると
区画が1つだけになり、構成比の情報がゼロになるため。

**4つのスタイルすべてがこの規則に従う。** スタイルごとに集計単位を変えない。

### R1. 4つのスタイルを用意する

`String` の rawValue を持つ enum とし、表示名は型側の `var title: String` に置く。

| rawValue | 表示名 | 見た目 |
|---|---|---|
| `bar` | 帯 | 積み上げた1本の帯 |
| `ring` | リング | 同心のリング |
| `bubble` | バブル | 面積が金額を表す円。ズームで細部を見る |
| `column` | 縦バー | 横スクロールで全件を見る |

集計単位はスタイルではなく**期間**で決まる（R0）。

**C・Dの工夫（ズーム・横スクロール）は、要素が多い月間換算で活きる。**
年間換算（最大4要素）では工夫が空振りするが、規則を単純に保つことを優先する。

### R2. 色の決め方

R0 の集計単位に従う。**色は集計単位から自動的に決まり、別の規則を持たない。**

- **種別ごとに集計するとき**（年間換算・絞り込みなし）：`CostType.colorHex` の4色
- **費目ごとに出すとき**（月間換算、または絞り込み中）：`Subscription.colorHex`
  （利用者が費目に決めた色。一覧や詳細画面と見た目が揃う）

月間換算で種別色を使わない理由：**同じ種別の費目がすべて同色になり、
帯で隣接すると境目が見えなくなる**ため。

### R3. 見込みの表現

- 見込みで算出された要素は**半透明**で描く
- 実績と見込みが混在するときは、カードの説明文に既にある「・見込みを含む」を維持する
- **半透明だけに頼らない**：VoiceOver では「見込み」と読み上げる

### R4. スタイルCの操作（バブル）

- 面積が金額に比例する円で表す
- **初期表示はすべてのバブルが収まる倍率**にする
- ピンチでズームイン／アウト、ダブルタップで初期倍率へ戻す
- **等倍（初期倍率）のときはパンを受け付けず、カードのページ送りへ譲る**
- **ズームインしている間だけ1本指のドラッグでパンする**
- ズーム倍率の上限・下限を設ける（際限なく拡大縮小させない）
- 円が小さすぎてラベルが入らないものは、ズームインで読めるようになる

### R5. スタイルDの操作（縦バー）

- 金額の高い順に縦バーを並べ、**横スクロール（慣性）**で全件を見せる
- **カード本体のページ送りと視覚的に区別する**
  - グラフ領域の左右端にフェードをかけ、続きがあることを示す
  - 領域の背景を一段落とし、スクロールできる面であることを示す
- 内容が領域内に収まっているときは横スクロールを無効にする

### R6. スタイルの切り替え

- **設定画面の「テーマ」セクション**に「グラフの表示」を追加する
- 4つから選ぶ。**選択中のスタイルのプレビュー**を出す
- 保存は `UserDefaults`（**この端末のみ**。CloudKitのスキーマは変更しない）
- 既定は `bar`（積み上げ1本帯）

### R7. 共通の要件

- どのスタイルでも**タップで `ReportBreakdownSheet` を開ける**ようにし、全件と金額を確認できる
- 期間（月／年）の切り替えとカードの慣性スライドの挙動は**変更しない**
- アクセシビリティ文字サイズでは、グラフ領域が340ptへ広がる既存の挙動を維持する

## データモデル

### `ReportEntry` に種別を追加する

現在は `id` / `name` / `amount` / `colorHex` / `isEstimated` のみで、**種別を持っていない**。
種別で色分けするために `costType: CostType` を追加する。

`ReportCalculator.report(...)` が `Subscription.costType` から詰める。

### 種別ごとの集計

年間換算・絞り込みなしのときに使う。`[ReportEntry]` を種別ごとに畳んだ結果を返す型を追加する。

- 金額は合計
- **その種別に見込みが1件でも含まれていれば、その種別を見込み扱いにする**
- 金額が0の種別は出さない（既存のレポートが0円を除外している流儀に合わせる）

## 画面

### 設定画面

```
テーマ
  ボタンの色      ● 既定        >
  カードの色      ● 既定        >
  グラフの表示    帯            >
  既定に戻す
```

「既定に戻す」は**グラフの表示も含めて**戻す。

## 受け入れ条件

- [ ] 4つのスタイルすべてが表示でき、設定画面から切り替えられる
- [ ] アプリを再起動しても選んだスタイルが保たれる
- [ ] **年間換算・絞り込みなし**のとき、4スタイルすべてが種別ごとに集計され、種別の4色で描かれる
- [ ] **月間換算**のとき、4スタイルすべてが費目ごとに出て、費目の色で描かれる
- [ ] **年間換算でも種別で絞り込んでいるとき**は費目ごとに出る（区画が1つにならない）
- [ ] 見込みの要素が半透明で描かれ、VoiceOverで「見込み」と読み上げられる
- [ ] Cは初期表示で全バブルが収まり、ピンチで拡大縮小、ダブルタップで戻せる
- [ ] **Cが等倍のとき、左右スワイプでカードのページ送りが効く**
- [ ] **Cがズームイン中は、ドラッグでグラフがパンし、ページが変わらない**
- [ ] Dが横スクロールでき、慣性が効き、端にフェードが出る
- [ ] **Dの横スクロール中にカードのページが変わらない**
- [ ] 費目が0件・1件でもどのスタイルも破綻しない
- [ ] 金額がすべて同額でも、1件だけ極端に大きくても破綻しない
- [ ] 集計・レイアウト計算にユニットテストがある
- [ ] iOS 26（Liquid Glass）と iOS 17〜25（フォールバック）の両系統で破綻しない

## やらないこと

- カード本体の慣性スライドの作り直し
- 期間（月／年）の切り替え方法の変更
- スタイルごとに別々の色設定を持たせること（テーマ色の設定は現状のまま）
- iCloud経由でのスタイル設定の同期
- グラフからの編集・削除などの操作（見るだけ）

## 制約・リスク

- **入れ子の横スクロール（D）は、内側が端に達しても同じ指の動きではページ送りに繋がらない**。
  SwiftUIの制約。指を離して再スワイプが必要になる
- **バブルの配置（circle packing）は自前で書く必要がある**。件数が変わるたびに
  レイアウトが動くため、アニメーションの調整が要る
- グラフ領域は130pt（アクセシビリティ文字サイズで340pt）と狭い。
  **C・Dはこの高さで成立するか、実装後に必ず目視で確かめる**
- `feat/cost-type-data-model` と `feat/theme-color` が未マージ。
  **マージ順は 固定費 → テーマ色 → 本サイクル**になる
