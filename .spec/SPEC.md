# SPEC - 要件定義

対象：Subsc iOSネイティブ版（`ios/Subsc`）。1.0.0 に含める。

## 目的

サブスクだけでなく、通信費・光熱費・その他の固定費もまとめて記録し、
**毎月出ていくお金の合計**を1画面で把握できるようにする。

金額が毎月変わる費目（光熱費など）は月ごとの実績を積み上げ、過去のレポートが
実際に支払った額になるようにする。

## 用語

- **種別（CostType）**：サブスク／通信費／光熱費／その他固定費。今回追加する概念
- **カテゴリ**：既存の「エンタメ」「仕事」など。種別の下位にある自由な分類。**今回は変更しない**
- **変動費**：金額が毎月変わる費目。項目ごとにフラグで指定する
- **実績（AmountEntry）**：変動費の「その月いくらだったか」の記録

## 要件

### R1. 種別を追加する

- 種別は**固定の4つ**：`subscription`（サブスク）／`communication`（通信費）／`utility`（光熱費）／`fixed`（その他固定費）
- `String` の rawValue を持つ enum とし、表示名は型側の `var title: String` に置く
- 登録・編集フォームで選択する。既定は「サブスク」
- **既存データはすべて「サブスク」になる**（保存プロパティの既定値で吸収する）

### R2. 変動費を扱えるようにする

- 種別とは独立した**「金額が毎月変わる」トグル**を持つ。既定はオフ
  - 通信費でも定額プランはあり、種別だけでは決まらないため
- オンのとき、金額は月ごとの実績として記録する
- 実績は「年月」と「金額」を持ち、1つの費目につき同じ年月の実績は1件だけとする
  - CloudKitの制約で一意制約が使えないため、**保存時に同じ年月の既存レコードを探して上書きする**
- 定額（トグルがオフ）の費目の扱いは現在と変わらない

### R3. 実績が未入力の月の金額

優先順に採用する。

1. その月の実績があればその金額
2. なければ**その月より前で最も新しい実績**の金額（＝直近の実績で見込む）
3. 実績が1件もなければ 0 円

2 を採用した月は**見込みであることが分かる印**を表示する（実績と混同させない）。

### R4. 未入力のリマインド通知

- **月末に、その月の実績が未入力の変動費があれば通知する**
- 対象：「金額が毎月変わる」がオンで、その月の実績が無く、利用状況が「利用中」の費目
- 配信日：その月の最終日。時刻は費目に設定済みの通知時刻を使う
- 実績が入力されたら、その月のリマインドは取り消す
- 既存の更新日通知とは別の識別子体系にし、片方の再スケジュールがもう片方を消さないようにする

### R5. 支払い方法

- 選択肢：未設定／クレジットカード／口座振替／コンビニ払い／その他。既定は「未設定」
- 加えて**自由入力のメモ**を持つ（例：「◯◯カード」）。空でよい
- 今回は集計に使わない。表示と記録のみ

### R6. 一覧の絞り込み

- 一覧に**種別での絞り込み**を追加する
- 既存の状態（すべて／利用中／停止中／履歴）と検索は維持する

### R7. レポート

- 既定は**全種別の合計**を表示する
- **種別で絞り込める**ようにする
- 変動費は R3 の金額で集計する
- 期間の切り替え（月／年）と慣性スライドの挙動は変更しない

## データモデル

### `Subscription` に追加する保存プロパティ

CloudKitミラーリングの制約により、**すべて既定値を持たせる**。

| プロパティ | 型 | 既定値 | 用途 |
|---|---|---|---|
| `costTypeRaw` | `String` | `"subscription"` | 種別 |
| `hasVariableAmount` | `Bool` | `false` | 金額が毎月変わるか |
| `paymentMethodRaw` | `String` | `"unspecified"` | 支払い方法 |
| `paymentMethodNote` | `String` | `""` | 支払い方法の補足 |

enum は直接保存せず、`~Raw: String` で保存して computed property で型付きの値を出し入れする（既存の `stateRaw` と同じ流儀）。

### 新モデル `AmountEntry`

変動費の月次実績。`final class` の `@Model`。

| プロパティ | 型 | 既定値 | 用途 |
|---|---|---|---|
| `clientID` | `String` | `UUID().uuidString` | 識別子（`@Attribute(.unique)` は使わない） |
| `year` | `Int` | `0` | 対象年 |
| `month` | `Int` | `0` | 対象月（年集計のみの費目でも月で持つ） |
| `amount` | `Double` | `0` | その月の金額 |
| `recordedAt` | `Date` | `.now` | 記録日時 |
| `subscription` | `Subscription?` | `nil` | 逆リレーション |

- `Subscription` 側に `amountEntries: [AmountEntry]?`（Optional）を持たせ、逆リレーションを張る
- **CloudKitミラーリングではリレーションを非Optionalにできない**ため、両側ともOptionalにする
- 配列や辞書を直に保存しない制約は、リレーションで代替するので抵触しない

### モデル名を変えない理由

`Subscription` という名前は実態（固定費全般）と合わなくなるが、**改名しない**。
SwiftDataのクラス名がCloudKitのRecord Type名になるため、改名すると既存ユーザーの
データが読めなくなる。doc コメントで「サブスクに限らず固定費全般を表す」と明記して補う。

## 画面

### 追加・編集フォーム

- 「サービス」セクションの先頭に**種別**のPickerを追加
- 「料金」セクションに**「金額が毎月変わる」トグル**を追加
  - オンのとき、金額欄のラベルを「今月の金額」に変え、保存時に当月の実績として記録する
  - オフに戻したときは、それ以降は定額として扱う（過去の実績は消さない）
- 「その他」セクションに**支払い方法**のPickerと補足メモを追加

### 詳細画面

- 種別と支払い方法を表示する
- 変動費のとき、**月別の記録**セクションを追加する
  - 直近12件を新しい順に表示
  - 「今月の金額を記録」から入力・修正できる
  - 見込みで計算されている月はその旨を示す

### ダッシュボード

- レポートカードに種別の絞り込みを追加（R7）
- 一覧の絞り込みに種別を追加（R6）

## 受け入れ条件

- [ ] 既存の登録データが「サブスク」種別として、金額・更新日・通知を保ったまま表示される
- [ ] 通信費・光熱費・その他固定費として新規登録でき、一覧とレポートに反映される
- [ ] 「金額が毎月変わる」をオンにした費目で、月ごとに違う金額を記録でき、過去月のレポートがその月の実績額になる
- [ ] 実績が無い月は直近の実績で計算され、見込みであることが画面上で分かる
- [ ] 実績が1件も無い変動費は 0 円として扱われ、クラッシュしない
- [ ] 月末に未入力のリマインド通知が届き、実績を入力するとその月のリマインドが消える
- [ ] 更新日の通知とリマインド通知が互いを打ち消さない
- [ ] 支払い方法を選択・保存でき、補足メモが空でも保存できる
- [ ] 一覧とレポートを種別で絞り込める
- [ ] ユニットテストが全件成功し、`ReportCalculator` の変動費まわりに新規テストがある
- [ ] CloudKit Console の Development 環境に `AmountEntry` と新フィールドが作成されていることを確認済み

## やらないこと

- 既存の**カテゴリ**の仕組みには手を入れない
- 支払い方法での集計・絞り込み（記録のみ）
- 銀行やカードとの連携、明細の自動取り込み
- 種別のユーザー追加（固定4種類とする）
- Web/PWA版への反映（廃止予定のため）
- モデル名の変更（上記の理由）

## 制約・リスク

- **CloudKitのRecord Typeを新規追加する。** Development で代表データを保存して
  CloudKit Console で差分を確認してから Production へ反映する（AGENTS.md の手順に従う）
- **1.0.0 に含める判断のため、リリースが後ろ倒しになる。** ストア掲載文・キーワードも
  「サブスク管理」から「固定費管理」へ書き直しが必要
- 審査向けの前提（独自ログインなし、データは端末と本人のiCloud Private DBのみ、
  為替APIへ費目名や料金を送信しない、アプリ内課金なし）は**維持する**
