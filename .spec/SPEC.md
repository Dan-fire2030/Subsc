# SPEC - アーカイブ機能

**確定日：2026-08-11**（`AskUserQuestion` で7件の方針をharutoさんが決定）
ブランチ：`feat/archive`（ベースは `main`）

前サイクル（カレンダーと一覧の使い勝手・ビルド17）の記録は `.spec/archive/*-2026-08-11-usability.md`。

## 目的

**「消したいが、消し切るのは怖い」を受け止める場所を作る。**
いまは削除しかなく、押した瞬間に取り返しがつかない。30日の猶予を挟む。

---

## 【最重要】CloudKit の Production 反映が必要

**この機能は `@Model` にフィールドを足すため、CloudKit の Production へスキーマを反映しないと
配布したビルドで同期が壊れる。反映は不可逆**（一度作った Record Type / Field は削除できない）。

追加するフィールド：

| モデル | プロパティ | 型 | CloudKit上の名前 |
|---|---|---|---|
| `Subscription` | `archivedAt` | `Date?` | `CD_archivedAt` |
| `Loan` | `archivedAt` | `Date?` | `CD_archivedAt` |

- **どちらも Optional。** CloudKitミラーリングの制約（非Optionalかつ既定値なしを許さない）を満たす
- **Optional は値を保存するまでフィールドが作られない。** Development署名のアプリで
  実際にアーカイブして保存し、CloudKit Console に出てから Production へ反映する
- **反映前に、モデルの保存プロパティと Console のフィールドを1件ずつ突き合わせる**
- **Deploy を押す前に差分を一覧で提示し、`AskUserQuestion` で承認を得る。不可逆であることを明示する**

**なぜ「状態（enum）」ではなく日時にするのか。** 30日の期限を測るのに、いつアーカイブしたかが要る。
状態だけ持つと日付を別に持つことになり、2つが食い違いうる。**日時1つで「アーカイブ中か」と
「あと何日か」の両方が決まる**（`archivedAt == nil` がアーカイブしていない状態）。

---

## 1. アーカイブする

- **対象は費目と借入の両方**（harutoさんの決定）
- 入口は2つ：
  - **詳細画面**：削除ボタンの上に「アーカイブ」を置く。**削除は残す**
  - **一覧の右スワイプ**：「アーカイブ」と「削除」を並べる
- **アーカイブに確認は出さない**（harutoさんの決定）。30日間は復元できるため。
  代わりに**「復元」で戻せる短い知らせ**を出す
- アーカイブすると `archivedAt` に現在時刻が入る
- **予約済みの通知は取り消す**（一覧から消えたものの更新日が届くのはおかしい）
- **借入の返済予定表は消さない。** 消すと復元できなくなる

## 2. アーカイブ中の扱い

**すべてから外す**（harutoさんの決定）。ゴミ箱として一貫させる。

- 一覧（すべて／利用中／停止中／履歴のどれにも出ない）
- レポート（**過去の月からも外れる**。承知のうえでの決定）
- カレンダー
- 通知
- 検索候補

**`ReportCalculator.includes` と `DashboardListBuilder` の入口で外す。**
判断を各画面へ写さない（カレンダーで同じ轍を踏まないため）。

## 3. アーカイブ欄

- **一覧の絞り込みに「アーカイブ」を追加する**（harutoさんの決定）。
  段が5つ（すべて／利用中／停止中／履歴／アーカイブ）になる
- **行ごとに残り日数を出す**（例：`あと23日で削除`）。
  いつ消えるか分からないと復元の判断ができない
- **期限が近いもの（残り7日以下）は色を変える**
- 行ごとの操作：**復元**と**削除**
  - **復元**：`archivedAt` を `nil` に戻す。**アーカイブ前の状態（利用中／停止中）はそのまま**なので、
    元の状態へ戻る。通知を組み直す
  - **削除**：完全削除。**吹き出しの確認を出す**（取り消せないため）
- **「すべて削除」を置く**（harutoさんの決定）。
  **一発で全部消えるボタンなので、確認は必ず出し、件数を明記する**
- **アーカイブが空のときは「すべて削除」を出さない**

## 4. 30日で自動削除

- **期限は30日固定**
- 判定は **起動時**と**アーカイブ欄を開いたとき**の両方で走らせる。
  起動時だけだと、アプリを開きっぱなしで日をまたいだときに消えない
- **「30日経った」の判定は日付の境目で行う**（`startOfDay` 同士で比べる）。
  時刻で比べると、同じ日なのに消える・消えないが分かれる
- **端末を開かないと消えない。** バックグラウンドで消す仕組みは持たない（既知の制約として記録する）
- 削除時は**予約済み通知も取り消す**

## テストで縛る

判断は**ビューではなくテストできる型**に置く（`ArchivePolicy` 仮称）。
`now` と `calendar` は既定値付き引数で注入し、実行日に依存させない。

- アーカイブ中かどうかの判定（`archivedAt == nil` / 値あり）
- 残り日数（29日目・30日目・31日目の境目。**日付の境目で切り替わること**）
- 期限切れの抽出（30日ちょうどは**まだ残る**／31日目で消える）
- **アーカイブ中が一覧・レポート・カレンダーのすべてから外れること**
- 復元で元の状態（利用中／停止中）へ戻ること
- **アーカイブしても借入の返済予定表が消えないこと**

## やらないこと

- 30日の長さを設定で変えられるようにする
- アーカイブの中での検索・並び替え
- アーカイブしたものをレポートの「過去分」に残す（**外す判断で確定**）
- バックグラウンドでの自動削除

## 受け入れ条件

- [ ] 詳細画面と一覧のスワイプからアーカイブできる。**削除も残っている**
- [ ] アーカイブすると一覧・レポート・カレンダー・通知から消える
- [ ] 絞り込みに「アーカイブ」が出て、行ごとに残り日数が出る
- [ ] 復元で元の状態へ戻り、通知が組み直される
- [ ] アーカイブ欄から個別削除できる（吹き出しの確認あり）
- [ ] 「すべて削除」が件数付きの確認を出し、空のときは出ない
- [ ] 31日目に自動で消える。30日ちょうどでは消えない
- [ ] ユニットテストが通り、**既存の527件が1件も落ちない**
- [ ] **CloudKit の Production へ反映済み**（承認を得てから）
