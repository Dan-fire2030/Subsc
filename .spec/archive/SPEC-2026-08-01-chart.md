# SPEC - 要件定義

対象：Subsc iOSネイティブ版（`ios/Subsc`）。テーマ色の設定。

> **状態：確定（2026-08-01）。**

## 目的

アプリの見た目を利用者が選べるようにする。現在はボタンもカードも青系に固定されており、
好みに合わせて変えられない。

**ボタン色とカード色を別々に**設定できるようにし、費目の内容に関わらず
アプリ全体の色味を利用者が決められる状態にする。

## 用語

- **ボタン色**：アプリ全体のアクセント色（`.tint`）。タブバー、リンク、主要ボタンに効く
- **カード色**：レポートカードの背景グラデーションと、それに連動する画面背景・空状態などの装飾色
- **プリセット**：あらかじめ用意した色。名前を持つ
- **カスタム色**：`ColorPicker` で利用者が自由に選んだ色

## 要件

### R1. 設定画面に2つの色設定を置く

- 設定画面に「テーマ」セクションを追加し、**「ボタンの色」**と**「カードの色」**の2項目を置く
- それぞれ独立して設定でき、片方だけ変えられる
- 各項目は現在の色を丸などで示し、タップすると選択画面（またはシート）を開く
- **既定値は現在の色**（ボタン：`Color(red: 0.08, green: 0.45, blue: 0.98)`、カード：青→紫→シアン）
- **「既定に戻す」を用意する**。自由選択で破綻した状態から復帰できるようにするため

### R2. 色の選び方

- **プリセットを並べ、加えて「その他の色」から `ColorPicker` を開ける**
- プリセットは名前を持ち、既存の費目カラー（`SubscriptionFormView+CategoryColor.swift`）と
  同じ流儀で `title` を型側に置く
- プリセットは**既存の費目カラーと同じ5色**：ブルー `#007AFF` / グリーン `#34C759` /
  ピンク `#FF375F` / パープル `#AF52DE` / オレンジ `#FF9F0A`
  - `SubscriptionFormView.swift` の `colorPresets` と `SubscriptionFormView+CategoryColor.swift` の
    名前定義に**すでに同じ5色がある**。定義を1箇所へ寄せて共用し、重複を作らない

### R3. カード色は1色の選択からグラデーションを生成する

カードは単色ではなく**青→紫→シアンの3色グラデーション＋発光する円2つ**で構成されている。
単純に1色で塗ると立体感が失われるため、**選んだ色を基準に色相をずらして3色を生成する**。

- 基準色の色相を `-17°` / `0` / `+40°` ずらし、彩度・明度に倍率をかけた3色で作る
  （既定色を入れると元のデザイン（青→紫→シアン）が再現される値）
- **生成した各停止色にも、基準色と同じ輝度の補正を個別にかける**
  - 色相と明度をずらすと輝度が動くため、基準色だけ補正してもグラデーションの端が保証されない
  - 2026-08-01のレビューで発覚。既定色の3色目が 3.15:1、プリセットのブルーで 2.62:1 だった
  - **元のデザインも 3.07:1 だった**ので、この補正は既存の弱点も解消している
- 発光する円の色も生成した停止色から導出する

### R4. 可読性を壊さない

カード上の文字は白で描かれている。**暗すぎる／薄すぎる色を選ぶと文字が読めなくなる。**

**選んだ色の明度・彩度を、白文字が読める範囲へ自動で収める。** 文字色は白のまま変えない。

- 利用者は「選んだ色に近いが、必ず読める色」を得る。**失敗できない**ことを優先する
- 収める範囲は実装時に決め、**ユニットテストで下限・上限を固定する**
- 極端な色（真っ白・真っ黒・彩度0）を入れても破綻しないことをテストで担保する
- 補正は**カード色にのみ**適用する。ボタン色は白文字の下地にならないため補正しない
  （ただしタブバーで見えなくなる極端な色は避けたいので、明度の下限のみ設ける）

### R5. 適用範囲

**ボタン色を適用する場所**

- `App/RootView.swift:41` の `.tint(...)`（タブバー・リンク・主要ボタンに波及）

**カード色を適用する場所**

- `Features/Dashboard/ReportGlassStyle.swift` の `LiquidGlassCardBackground`（3色グラデーションと円2つ）
- 同ファイルの `glassEffect(.regular.tint(.blue...))` と影の色
- `App/RootView.swift:89` 付近の画面背景グラデーション（`AppLiquidGlassBackground`）
- `Features/Settings/SettingsView.swift:23,30` のヘッダーアイコンと影
- `Features/Dashboard/DashboardEmptyState.swift:12,17` の空状態
- `Features/Dashboard/DashboardView.swift:101` のグラデーション
- `Features/Subscriptions/NotificationTimingView.swift:24,44` のチェック色

**適用しない場所**

- 費目ごとのカラー（`Subscription.colorHex`）。利用者が費目単位で選ぶ既存の仕組みで、別概念
- 状態を示す色（利用中／停止中の緑・オレンジ、削除の赤）。**意味を持つ色なのでテーマで変えない**

### R6. 保存

- `UserDefaults` に保存する。**この端末のみ**で、iCloud同期しない
  - 当初は `@AppStorage` と書いていたが、**`@Observable` なクラスとは併用できない**ため
    `ThemeStore` が `UserDefaults` を直接読み書きする形にした（2026-08-01に実装側へ合わせて修正）
  - `UserDefaults` は既定値つき引数で注入し、テストが実行者本人の設定を汚さないようにする
- **CloudKitのスキーマは変更しない**（Production反映が進行中のため、影響を出さない）
- 保存する値は色の16進文字列。プリセットもカスタムも同じ形式で保存し、区別を持たない

## 画面

### 設定画面

```
テーマ
  ボタンの色    ● ブルー        >
  カードの色    ● ブルー        >
  既定に戻す
```

### 色選択画面

- プリセットを名前つきで一覧表示し、選択中に印を付ける
- 末尾に「その他の色」を置き、`ColorPicker` を開く
- **選択結果をその場でプレビューする**（カード色はレポートカードの縮小版を出す）

## 受け入れ条件

- [ ] 設定画面でボタン色とカード色を別々に変更でき、アプリ全体へ即座に反映される
- [ ] アプリを再起動しても選んだ色が保たれる
- [ ] プリセットから選べる／`ColorPicker` で任意の色も選べる
- [ ] カードのグラデーションが1色の選択から生成され、元のデザインの立体感が保たれる
- [ ] 極端に暗い色・薄い色を選んでもカード上の文字が読める
- [ ] 「既定に戻す」で元の配色へ戻る
- [ ] 利用中／停止中などの状態色はテーマを変えても変わらない
- [ ] CloudKitのスキーマに変更が出ていない（Console の Development に差分が出ない）
- [ ] 色の変換・生成ロジックにユニットテストがある
- [ ] iOS 26（Liquid Glass）と iOS 17〜25（フォールバック）の両系統で破綻しない

## やらないこと

- 費目ごとのカラー設定の変更
- ダークモード／ライトモードの強制切り替え
- 配色プリセット（ボタンとカードの組み合わせ）としての提供。今回は個別に選ぶ
- iCloud経由での設定同期
- 状態色（緑・オレンジ・赤）のテーマ化

## 確認したいこと

- **iOS 26 実機での見え方**。Liquid Glass はシミュレーターと実機で差が出るため、
  実装後に haruto さんへ実機確認を依頼する（エージェントは代行できない）

## 制約・リスク

- 固定費機能（`feat/cost-type-data-model`）が main へ未マージ。本サイクルはその上に積んでいるため、
  **マージは固定費機能 → テーマ色の順**になる
- iOS 26 の `glassEffect(.regular.tint(...))` は下地を透過するため、
  **同じ色でも iOS 17〜25 のフォールバックと見え方が変わる**。両方で確認が要る
- 実機確認はユーザーの作業
