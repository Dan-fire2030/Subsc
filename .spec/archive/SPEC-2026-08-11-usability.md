# SPEC - カレンダーと一覧の使い勝手を直す

**確定日：2026-08-11**（`AskUserQuestion` で4件の方針をharutoさんが決定）
ブランチ：`feat/list-and-calendar-usability`（ベースは `main`）

## 全体の前提

- **保存するデータを増やさない。** `@Model` に触らないため **CloudKitスキーマの反映は不要**
- **表示の選択は `UserDefaults` に覚えさせる**（`ThemeStore` / `CalendarDisplayStore` と同じ流儀）
- **判断のロジックはビューに置かず、テストできる型へ閉じる**（既存の `DashboardListBuilder` の流儀に合わせる）
- 既存テスト503件を1件も落とさない

---

## 1. カレンダーの年月をホイールで選ぶ

**いま：** 見出し `2026年8月` の左右に矢印ボタン、加えて横スワイプ。遠い月へ行くのに何度も押す必要がある。

**こうする：**

- **見出しそのものをタップできるようにする。** タップするとホイールが出て、**年と月の2列**から選ぶ
- **矢印ボタンと横スワイプは残す。** 隣の月へ動く操作としては今のほうが速い
- 見出しがタップできることが分かるよう、**下向きの小さな山形（`chevron.down`）を文字の右に添える**
- 選ぶとその月へ移動し、**選択日はその月の同じ日**（月の日数を超える場合は末日へ丸める。既存の `clampedSelection` を通す）
- **年の範囲は、登録されているいちばん古い期日の年から、いちばん先の期日の年まで。**
  それが今年を含まない場合は今年も入れ、**前後に1年ずつ余裕を足す**。
  固定の範囲（例：2000〜2100）にしない。**選べる年が実際のデータと合っていないと、選ぶ意味がない**
- 出し方は **iOS 26 では Liquid Glass、iOS 17〜25 は従来の見た目**へフォールバックする（既存のスイッチと同じ作法）

**テストで縛る：** 年の範囲を組み立てる関数。データが空のとき／今年より過去だけのとき／未来だけのとき。

## 2. 費目一覧を月払いと年払いで分ける

**いま：** 費目と借入が「次の期日」で1本に混ざって並ぶ。月払いと年払いが隣り合うため、**金額の意味が揃っていない**。

**こうする：**

- 一覧を **「月払い」「年払い」のセクション**に分ける
- **各セクションの見出しに件数と合計を添える**（例：`月払い ・ 5件 ・ ¥12,340`）
- **合計は「そのセクションに並んでいる行の金額の合計」にする。**
  行が出している値（月払いは月額、年払いは年額、返済は次回返済額）をそのまま足す

  **2026-08-11に方針を変更した。** 当初は `ReportCalculator` を通す予定だったが、**成立しない**。
  `ReportCalculator` は期間ごとの集計で停止中・履歴を独自の規則で除くのに対し、
  一覧は絞り込み次第でそれらを表示する。レポートの数字を見出しに出すと
  **すぐ下に並ぶ行と合わない見出し**になる。見出しは、その下にある行についての要約であるべき
- **借入・ローンは「返済」の独立したセクション**にして先頭へ置く。
  借入には支払い周期の概念が無く、月払い・年払いのどちらにも入れられないため
- **既定で分類する。** 分類しない状態へ戻す切り替えは作らない（harutoさんの決定）
- **検索中は分類しない。** 探している最中に階層が増えると目的の行が遠くなる

**テストで縛る：** セクションの分け方と、各セクションの件数・合計。借入が「返済」へ入ること。
**行が出している金額とセクション合計が一致すること**（見出しが行と食い違わない不変条件）。

## 3. 費目一覧の並び替え

**いま：** `DashboardListBuilder.sorted` が「次の期日」順に固定。

**こうする：**

- **左上の絞り込みメニュー（`costTypeFilterMenu`）へ並び替えを追加する。** 入口を増やさない
- 選べるもの：**期日順 / 金額順 / 名前順**
- **既定は金額順（大きい順）**（harutoさんの決定）
- **昇順・降順を切り替えられる**ようにする
- 名前順は**日本語の並びで比較する**（`localizedStandardCompare`）。
  文字コード順だと、ひらがな・カタカナ・漢字が直感と違う並びになる
- **どの並びでも、最後は必ず名前で決める。**
  同額・同日で順序が決まらないと、**再描画のたびに行が入れ替わる**（カレンダーで同じ問題を踏んでいる）
- 選んだ並びは `UserDefaults` に覚えさせる

**テストで縛る：** 3つの並び順と昇降順。同額・同日のときに順序が安定すること。

## 4. 削除の確認を、押したボタンの近くに出す

**いま：** 削除の確認はすべて `confirmationDialog`。**押した場所と関係のない位置に出る**ため、
どのボタンに対する確認なのか一瞬迷う。

**こうする：**

- **削除の確認を `popover` に変え、押したボタンを起点に出す**
- iPhone でも吹き出しのまま出すため **`.presentationCompactAdaptation(.popover)`** を付ける
  （付けないとシートへ化ける）
- 中身は今と同じ：見出し・「削除」（`destructive`）・「キャンセル」
- **対象は削除の確認すべて**（harutoさんの決定）。**実際に該当したのは3箇所**：
  - `DashboardView` の一覧からの削除（スワイプ）→ **その行を起点にする**
  - `SubscriptionDetailView` の削除ボタン
  - `LoanDetailView` の削除ボタン

  **当初5箇所と書いたのは数え違い。** `LoanHistoryView` と `LoanPaymentEditorView` にあるのは
  「操作を完了できませんでした」という**別のアラート**だった。

- **`LoanPaymentEditorView` の「記録を取り消す」には、そもそも確認が無い**（押すと即実行）。
  位置の問題ではないため今回は触らない。**確認を足さない判断**（2026-08-11・harutoさん）。
  元の予定へ戻すだけでデータが消えるわけではないため
- **削除以外の確認（テーマを既定に戻す、操作の失敗の知らせ）は今のまま。**
  これらは特定のボタンに紐づかない、または画面全体に関わる知らせのため

**確認の観点：** ここはビューの見た目なので、ユニットテストでは縛れない。
**シミュレーターで5箇所すべてを開いて、吹き出しが元のボタンの近くに出ることを目で見る。**

## 5. 内訳シートの色をアプリの配色へ揃える

**いま：** `ReportBreakdownSheet` が **`ColorHex.color(from: entry.colorHex)`（保存値そのまま）** で描いている。
グラフ本体は `ReportChartPalette.color(for:)` を通して **`BlackCatPalette.harmonized` で黒猫の配色へ寄せている**。
**このシートだけ配色が取り残されている**のが、浮いて見える原因。

**こうする：**

- 内訳シートの色を **`BlackCatPalette.harmonized(from:)` を通した色**にする
- **グラデーションの作りは変えない**（色 → 同じ色の55%。harutoさんの指示）
- 見込みの薄さ（`estimatedOpacity = 0.45`）も既存の規則に合わせる
- **保存値は書き換えない。** 表示のときだけ寄せる（グラフ本体と同じ方針）

**テストで縛る：** 保存値の色を渡したとき、シートが使う色がグラフ本体と一致すること。

## やらないこと

- 保存プロパティの追加、`@Model` の変更
- 一覧への新しい入口の追加（並び替えは既存メニューへ入れる）
- 削除以外の確認の見た目の変更
- グラフの配色そのものの作り直し（**寄せ先は既存の `harmonized`**）

## 受け入れ条件

- [ ] カレンダーの見出しをタップして年月を選べる。矢印とスワイプも従来どおり動く
- [ ] 年の範囲が登録データに追従する
- [ ] 費目一覧が「返済」「月払い」「年払い」に分かれ、見出しに件数と合計が出る
- [ ] セクションの合計がレポートの数字と食い違わない
- [ ] 並び替えが3種類＋昇降で効き、既定が金額の大きい順
- [ ] 同額・同日でも再描画で行が入れ替わらない
- [ ] 削除の確認5箇所が、押したボタンの近くに吹き出しで出る（シミュレーターで目視）
- [ ] 内訳シートの色がグラフ本体と一致する。グラデーションは従来どおり
- [ ] ユニットテストが通り、**既存の503件が1件も落ちない**
- [ ] `@Model` に触っていない（CloudKit反映が不要であることの確認）
